# Domain 改进方案 v0.1：工程修复与流程选择分开

状态：供共同设计的方案草稿，未实施、未发起模型实验。依据[跨路径逐轮分析](2026-11-07_cross_runtime_trajectory_analysis.md)，并核对当前实现。用户将另行梳理人类建模师的理想流程、各环节能力及模型分工；本稿保留这些决策空间，不把当前工具链写成新的标准流程。

目标是让模型以较少的执行成本产出满足任务的 BIM。更快看完整交付时间，更好看建筑信息与可用性，更省看实际成本、算力及人工救火；工具数、token、检查次数只作为诊断指标。还需与用户共同明确不同任务的必要质量和合理简化，不能用删必要对象换速度。

## 一、两类问题的判断方法

**工程问题：在已约定的输入、输出和质量要求下，实现是否正确、稳定、可诊断、可修复。** 例如共享墙被规整程序拆开、合法修复无法提交、错误信息定位不准、回执丢失、状态误报。即使保留现在的建模方式，这些问题也值得修。

**流程问题：为了得到所需结果，是否需要采用我们规定的表示、步骤、工具和检查方式。** 例如是否必须逐项量测、是否必须先典型层后整栋、是否必须走某个构建工具、是否每次修改都重做某种复核。即使程序完全无bug，这些规定也可能对某种模型或任务不划算。

一个问题可以同时涉及两层，按具体决策拆分，不强行归入一个桶：

| 交界问题 | 工程层负责 | 流程/领域层共同决定 |
|---|---|---|
| 几何规整 | 合法共享关系不被破坏，数值行为稳定且可解释 | 是否规整、采用何种精度、对哪些对象适用 |
| 建模接口 | 契约清楚、版本一致、合法输入可写、失败可修 | 模型提交参数模板、直接几何、代码还是其他中间表达 |
| 修改后的复核 | 准确判断变更影响及证据是否仍有效 | 哪些变化需要重新看图，哪些结果可以复用 |
| 上下文 | 引用可解析、精确回读、状态不丢失 | 什么内容常驻、何时摘要/回读、如何呈现给模型 |
| 保留建筑信息 | 记录对象身份与变更，暴露删除/合并影响 | 哪些信息必要、哪些可以简化、哪些初稿解释应该推翻 |

“锁住所有初稿对象”不是合适的工程底线：最新成功运行需要删除错误推断的前厅/走廊墙。要保护的是有依据且任务需要的信息，并允许基于新证据纠正旧解释。

## 三、流程现状：哪些真的被规定了

核对[最新实跑guide](D:/Sim-BIM-Agent/cases/lee-garden-six-full-dsh-sol61-recovery-cold-20261106-2253/shared/guide.txt)后，不能说现状强制逐项量测或固定全套工具顺序：开头及后文已允许自主选择观察、工具和修订；剖切、像素比较等写为按问题选用。

仍有几类约束需要审视：

| 现状 | 约束性质 | 要讨论的内容 |
|---|---|---|
| 无固定阶段/工具序列；量测、剖切、数值比较按问题选用 | 已有自主空间 | 为什么实际仍出现高开销路径：来自任务本身、提示示例、接口可用性，还是模型策略？不能只加一句“工具可选”就算解决。 |
| 先读partial_inference；建议主体/标高/典型层；强调repeats、core_connections和patch批修 | 提示层的方法规定/偏好 | 哪些是有帮助的默认建议，哪些应成为可选方法，哪些仅特定任务需要？ |
| 单位、坐标变换、身份和连通一致；有效源几何与真实交付 | 产物和执行要求 | 保留必要结果条件，确认是否过度规定了中间表示。 |
| 当前mesh review要求至少一个绑定当前源模型的overlay ID；whole_building完成声明 | 代码层的证据出口约束 | 是否允许其他能核对最终工件的等价证据？证据一致性与视觉真实性要分别判断。它没有规定相机数量或辅助图量测次数。 |
| mesh review按整source哈希失效；图纸review已有部分物理scope复用 | 当前证据有效性实现 | 哪些变化只影响局部，哪些会传播；能否准确复用未变化部分，不能笼统说所有检查都必须重做整栋。 |
| 0.1m主参数、0.3m对齐、0.6m宽度等规则 | 当前领域精度/简化政策 | 各规则的用途、适用对象、例外及必要性，需结合人类建模流程决定。调整政策不是修数值bug。 |

## 四、流程改进候选：能力可用，路径按题选择

这里按能力维度组织讨论，不把各行规定成必须顺序执行的阶段。

| 设计议题 | 建议候选 | 应继续保证的结果 | 待验证问题 |
|---|---|---|---|
| 观察与量测 | 允许直接视觉判断清楚的对象、分隔、相邻和重复关系；有尺度、错位、歧义或数值要求时再调用相应量测。 | 有依据的尺度/坐标；观测、推断和采用值区分；不能凭信心虚构精度。 | 较少量测是否仍保留关键关系与足够精度？量测在哪些问题真正改变决策或减少返工？ |
| 建模表达与产出方式 | 比较直接提交共同源表示、参数模板/局部编辑、允许的代码或通用工具构造等路径；让它们通过一致的导入、校验和交付接口。现有generic build与parametric能力优先复用。 | 最终Sim-BIM JSON/HTML、必要语义和几何、来源/假设及可检查的交付。 | 每种模型/任务在哪条路径更省构造和修复成本？直接产出是否把负担转移到冗长声明或校验修复？ |
| 模板与重复 | 将典型层、重复实例、核心连接等作为减少输出/维护的能力；允许直接表达例外或不使用模板。 | 已观察重复与推断重复区分；独立空间与服务层门保留。 | 是模板在帮助模型，还是模型在迁就模板？何时模板表达的例外比直接编辑更昂贵？ |
| 构建时机与粒度 | 允许先快速形成可检查版本，也允许在证据充分后一次构建；局部试建和整栋构造作为候选。 | 草稿与正式交付状态分明；试建不把暂定解释当已确认事实。 | 早期可视化是否能更早暴露错读，还是增加编译、回看和上下文成本？ |
| 构建与修改 | 模型负责建筑语义和采用值；代码承担已明确关系的重复展开、坐标计算、共享边维护和确定性检查。高层编辑与局部底层编辑可作为候选。 | 修改范围可核对；必要对象不能为过检无解释消失；有证据时允许纠正初稿。 | 哪种表达能让模型清楚修改一个建筑意图，而不手改大量相关坐标？适合暴露多高层的操作需听取人类流程。 |
| 验证与停止 | 依据未解决问题和变更影响选择检查，复用仍有效的证据；把代码能确定的几何检查与需要看原图的建筑判断分开。 | 最终工件与输入相符到任务所需程度；已知必要修改已落盘；未知和合理简化明确。 | 哪些判断首次做一次就够，哪些局部修改必须重验？怎样知道“够用”，而非完成工具清单？ |
| 交付操作 | 评估模型是否需要填写当前审阅JSON并调用同名finish工具，或可用等价提交动作，由后端生成同等强度的交付证明。 | 明确选择最终版本、完成范围、剩余未知；交付证明绑定真实产物；不能自动把任意保存当完成。 | 哪些说明必须由模型判断，哪些ID、哈希和状态可以由代码填充？当前仍需真实finish，等价提交只是待设计候选。 |
| 工具与说明呈现 | 比较当前完整工具集、短入口加按需说明、按任务呈现能力等方式；原始资料和必要接口说明始终可取得。 | 不因隐藏工具让模型找不到必要能力，不因缩短上下文丢当前状态。 | 模型少看说明是否更快，还是增加发现/猜参轮次？全部可见与按需发现各自的净成本？ |
| 模型与程序分工 | 先按问题识别所需能力；需要时再测试不同模型或可选子任务。 | 总质量与总成本合格，包含父级验证及恢复成本。 | 较低成本模型在哪些有界子任务可用？分工收益是否大于调度、上下文和复核开销？不预定必须多Agent。 |

视觉能力较强的模型可能直接判断“这是一间连续办公区、这里没有实墙”，不必先运行像素剖面来证明同一事实；若要确定绝对高程、图纸映射或门在墙上的数值位置，则按现有依据和精度需求选择测量/计算支持。选择条件应来自当前问题、证据和可验证的结果，而非仅按模型名字贴“强/弱”标签或信任其自报信心。

“少调用工具”不是优化终点。一次有用的量测或检查若能避免整稿重写，应保留；模板、回叠和诊断也一样。最新成功运行的原图复查确实导致建筑解释和底商门窗修订，方案必须保护这种收益。

## 五、与人类建模流程的合并方式

用户的流程按实际建模思考来写即可，不需要迁就现有工具名称、API或本稿的分类。待提供后，由我们将每个实际决策对应到：

| 需要对齐的内容 | 要得到的设计信息 |
|---|---|
| 此时要回答什么建筑问题，依据哪些资料 | 能力需求及证据入口 |
| 人类会直接判断、估计、量测还是试建；什么情况下换方法 | 可选方法与触发条件 |
| 哪些地方最需要经验，哪些是机械计算或重复劳动 | 模型、人、确定性代码的候选分工 |
| 产出什么中间信息，何时算足够确定 | 最小中间表达及质量要求 |
| 新证据或修改会影响哪些部分 | 依赖关系、局部修订和检查复用 |
| 什么可以简化，什么不能丢；何时停止 | 任务范围、可接受质量和交付条件 |

合并后的设计产物建议为：**建筑决策与能力对应表、可选产出路径、必须满足的结果条件、工具/实现改动及验证清单**。工具从这些需求中推导，不先用现有函数切出一套固定工序。

## 六、验证顺序与判据

1. **先固定工程基线。** 对E1–E3做离线失败片段和反例验证；E4保留现有回归，E5先记录组成。明确哪些改动只修实现，哪些改变质量政策或流程。以上是建议实施次序，本轮只完成方案。
2. **与用户对齐必要质量和能力。** 接收人类流程后确定输出范围、合理简化、精度及人工关注点；不以所有初稿对象或模型自填检查表充当GT。
3. **同一工具/模型/输入，先比较流程提示。** 保持工程基线、工具权限和结果条件一致，比较现有方法偏好与以结果为主的自主选择；观察量测、修复和复核行为如何变化。
4. **再分开验证表示与工具接口。** 参数模板与直接构造、现有编辑与高层编辑、全量信息与按需读取分别做窄题筛选；每轮列清实际改变的变量，不同时替换提示、工具、规则和宿主后作单因果结论。
5. **通过局部机制验证再做整案与留出案例。** 所有路径用共同结果检查和独立建筑评价，包含失败成本；防止只适配利苑。确认好用后才决定默认值，其他有效路径可以继续保留。

评价至少包括：必要建筑信息/空间关系/外形与开口保留，完整交付率及无人救火情况，端到端耗时及分段请求/工具时间，实际用量和可获得的账单成本，修复次数与语义损失。样本不足就报告单次现象与不确定性，不承诺固定提速比例。工具数量、初稿时间和finish成功都不能单独代表整体收益。

## 七、本稿可先确定与暂留的决策

可先确定的工程方向是：合法输入不被实现破坏、错误能定位且有修复出口、回执与执行一致、当前资料可准确取得。建议E1/E3先落地、E2最小复现同步推进；E4保持验证，E5先量化。

留待共同设计：视觉/量测的边界、适合的建模表达与中间产物、领域精度规则、必要建筑信息、检查和停止条件、哪些工具有净收益，以及是否/如何做模型分工。自研runtime与DSH继续作为可用路径，不在本稿选定替代关系。
