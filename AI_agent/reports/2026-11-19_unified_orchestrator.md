# 统一 Sim-BIM 主控与双宿主整案验证

目标是让主控根据图纸、GLB 和建筑说明的实际证据，自行决定建模细度、观察方式、委派和复核。产品以建筑模拟为用途。明确的空间边界、门窗及通达关系应当保留，资料缺失处允许有限推断。此次交付范围为开发仓库。德福未纳入质量参照，置信度视图和交付后的交互调整留待后续。

最终代码在 DeepSeek Harness 上从原始材料独立交付了两个案例。SM25 与历史 6.1 Sol 的满分参照持平。利园六期按整栋轻量模拟的范围有保留通过，办公与沿街零售的独立入口得到恢复，首层边界、餐厅侧门定位和顶部渐收窗带仍有误差。两案均由主控自行决定何时读图、派工、改模和交付，中途没有人工提示或替它改模型。此结论来自开发期间复用的两案，尚待新楼验证泛化。

## 代码与执行

改动前已将经过验证的订阅接入单独提交为 `c71ba4d3`，标记为 `baseline/pre-unified-orchestrator-20261119`。开发分支为 `codex/unified-orchestrator`。另有本地保护分支保存原有跟踪文档的工作状态，历史运行资料未混入代码。

产品命令接受 `mode: orchestrator`，材料集中在 `materials`，图片按原文件名关联自然语言。默认宿主是 DeepSeek Harness。`runtime: native` 使用自研宿主。主控持有当前 BIM，可自行观察和修改，也可以委派有界的只读任务。子任务回传结构化观察、来源和不确定性，支持按任务 ID 复用。同一份源模型和查看器由真实的 `finish_bim` 回执绑定。技术交付和独立建筑评价分别记录。

本轮模型全部走项目独立授权的 ChatGPT 订阅。三种模型都完成了真实图片和本地工具的窄验证。DSH 负责主控循环，Terra worker 通过 MCP 调用项目共用的子任务执行器。配置 worker 时，DSH 将总请求、工具预算的约四分之一留给 worker 池，自研宿主在整个任务树动态共享总额。两侧逐项核对成本，宿主差异和同期运行负载均影响用时解释。

## 已观察到的工程问题

首轮 SM25 的 DSH 主控在读过六张图后派工，Windows 下的 Git 配置探针继承了 MCP 标准输入，导致子任务阻塞。该次尝试已终止并保存，未交付模型。修订后 Git 探针使用独立空输入，纯图与混合输入的真实 stdio MCP 离线回归能完成委派和重用。

第二轮 DSH 在两个案例中均自主派工，但读图任务在发出 Terra 模型请求前返回 `InvalidURL`，主控随后自行继续。排查在实际 DSH 子进程环境复现了其 IPv6 loopback 排除项与 HTTP 客户端代理解析之间的不兼容。自研对照的 Terra 已产生真实响应，故此问题定位在宿主接线。两次工程失败计入过程评价。

修复后的 DSH 窄测通过真实订阅调用 Terra。原图 SHA、观察结果及不确定性随工具回执进入主控下一次上游请求。随后整案冷启动暴露了安装版 DSH MCP 客户端默认的 60 秒超时。利园两项委派分别在约 60.4 和 60.8 秒处被中断，SM25 也复现。现由案例墙钟上限约束 MCP 调用，子任务自身保留独立的预算。再次冷启动时，SM25 的两项观察均完成，较长一项用时约 121 秒。利园两项也完成，较长一项约 95 秒。原始工具和模型回执保存在各次执行的 `control` 和 `private/workers` 内。

自研宿主首轮 SM25 在完成一层后，主控调用 `read_context_image` 37 次。一次 SHA 不符被拒，36 次成功调取的图都确实进入下一次请求，但四张待比较的图只能在最近三个批次中轮换。现允许连续、精确的归档读图暂时组成同一比较组，按原图身份去重。上下文压力或图片预算触顶时仍能回收。用旧轨迹相同的原图重新构造请求，第 15 轮能首次同时提交这四张图，四个 SHA 与冻结输入逐一对应。复现资料在批次的 `method-check/native-image-replay/`。

利园第四轮的初次委派把 23/F 平面和整栋分层、窗带分给两个 Terra。主控在首个有效候选中明确引用 worker 的上下窗带读数，并结合自己对网格的量测。第五轮的主控先委派 23/F 核心区，自己量测立面，之后才将屋顶轮廓和高程另行委派。两次运行都由模型决定拆分。对第四轮还逐字节核对了 DSH 的工具回执截短。两项 worker 的建筑结论均已到达主控，两条网格测量摘要的中段被省略。用正式的 `read_worker` 和对应 measurement ID 可完整读回，见批次 `method-check/lee-worker-receipts/round-06.json`。

从 `domain-v177 / runtime-v54` 起，统一网格任务可依据已获资料直接声明覆盖范围，也可以按需回叠。系统核对源模型、原始输入及所有引用的回叠文件，查看器区分模型的范围声明与建筑质量评价。利园的任务书明确要求回叠，因此继续按这一要求验收。旧网格入口保留原交付约定。

利园第五轮在屋顶委派上遇到两个问题。一是 Terra 把网格剖面当作原始图纸，填入可选的结构化图纸读数。即使其余六条观察有效，整份回答也无法通过来源核对，原纠错信息使它在同一字段上又错了一次。修订后会点出具体条目、文件名及引用，允许纯网格任务将相应内容留在具备证据的观察与解释中。用该任务的原图像和工具回执向 Terra 发出一次真实订阅纠错请求，收到七条有效直接观察，六条绑定既有量测。两组屋顶轮廓得到保留。二是主控尝试读回三个原视图和三项量测时，DSH 的 JSON 检查拒绝了网格法向量中的负零。观察服务现复用 BIM 工具已有的数值输出处理。在同一安装版 DSH 的本地回放中，下一次请求收到三个原始 PNG、31 个三维坐标和两组剖面线，图像与证据哈希相同。见批次中的 `method-check/lee-roof-repair/report.json` 和 `method-check/dsh-worker-output/r5-host-new-report.json`。两项修改记录于 `domain-v178 / runtime-v54`。
