# Sim BIM Agent 价值诊断与迭代方案（获批前快照）

日期：2026-10-25。本文保存诊断与方案快照；用户随后已批准推进，实施与实测状态见[当前交接](2026-10-25_harness_value_iteration.md)。本文不作为已实施或达标报告。

本轮按用户授权读取历史轨迹、重放确定性几何、执行少量缓存探针。没有修改产品代码、默认模型、提示词或桌面发布，没有新增整楼生成或运行 EnergyPlus。诊断脚本和详细证据位于 `D:/Sim-BIM-Agent/cases/harness-value-investigation-20261025/`。

## 1. 本轮要回答的问题

毕设的目标是从多模态资料生成 Sim BIM，并用于真实街区仿真。Agent 的价值必须体现为可重复的交付收益，不能以工具数量、规则长度、检查次数或自建 runtime 的存在代替。

用户给定的目标同时保留：

- 更快：相对同模型通用 Agent，完整合格交付至少快一半；幸福中心、利苑单 Agent 均在 10 分钟内。
- 更好：主要形体与立面忠于资料，空间组织和推断更合理；已有正确细节保留，不为“做粗”而删除。
- 更省：统计整次任务的输入、缓存输入、输出、失败重试和成本；同模型省 token，或较便宜模型也能稳定达到质量门槛。
- 后续分工目标是 5 分钟，但先把单 Agent 工序做好。并行诊断人员不等于产品已经切换多 Agent。

“10 分钟”指完整交付，不是首稿；超时保留的可查看候选不自动算成功。速度、质量、成本分别报告，任何一项未满足都明确保留。

本轮证据不足以证明现有 harness 优于通用 Codex。用户已指出平面精度没有稳定优势，本文不再用个别指标或模型自评恢复这个结论。

### 2.1 首稿之前：现成工具省掉了底层编程，却没有省掉足够的模型工作

幸福中心首稿前的 13:30 中，模型请求约 12:06，工具约 51 秒，其余约 33 秒。模型请求包含推理、生成、服务端计算和网络等待，不能把它全部称为“建筑思考”。

| 区间 | 可观察工作 | 耗时与解释 |
|---|---|---|
| 0–5:02 | mesh 方向、立面、剖切、像素量测、平面观察，穿插读取 8 份参考 | 观察和接口学习混合；8 份原始参考约 64,156 字符，取文件本身仅 0.33 秒，无法从日志单独计量阅读时间 |
| 5:04–10:24 | 输出首份参数化声明 | 单次请求 5:21；输出 11,928 tokens，其中约 8,214 是非 reasoning 输出；工具参数约 23,739 字符 |
| 10:25–12:30 | 修正内核孔洞与门宿主，改写连接表达，新增底层模板 | 既包含真实几何错误，也包含接口适配和底层例外表达，不应全部记为建筑推断 |
| 12:30–13:30 | 修正推断屋顶空间的局部净宽阈值后保存 | 约 32 秒模型请求和 26 秒工具；没有新增读图 |

首次拒绝中的门确实不在房间边界上，属于模型提出的几何矛盾，检查有价值。与此同时，连续消防梯与连续楼梯之间的连接不适用现有 `core_connections` 的“本层空间到连续核心”快捷表达，模型改写了 13 条逐层门。重复坐标与重复声明没有增加 13 次建筑判断。

Codex 也花约 5 分钟编写首个生成脚本，首份文件前有五次程序/几何错误并自行修复。当前对照不能表述为“我们修很多，Codex 一次生成就全对”。我们已经提供几何内核，却仍让模型生成和维护大量接口声明。现成内核尚未转化为显著的交付速度优势；长声明及修复是已观察到的候选原因，具体贡献仍需消融验证。

### 2.2 确定性规整在制造部分返工

利苑历史草稿的离线重放复现了原审计拒绝，拒绝数组逐字段一致：

- 共享节点附近的原始局部平面覆盖及直线重叠检查通过，共同节点经各边分别按 0.1 m 网格规整后，被拆成相距约 8.46 mm / 34.82 mm 的点，再因节点不共用被拒绝。这不表示原始整栋模型已全部合格。
- 一次门宿主不匹配的端点偏差只有约 0.0608 mm，声明中的独立近似坐标没有保持精确共线；没有证据表明 JSON 序列化本身改变了数值。
- 另有推断管井旁 0.2 m 小台阶触发 0.3 m 的局部宽度政策。这与“门未落到墙上”等数学错误不属于同一种问题。

这些证据支持先修几何身份和公差传播，而不是让模型反复挪点。用户要求的 10 cm 参考线目标仍保留；共同节点和边应先确定身份，再统一规整，不能每个房间分别取整后要求天然严丝合缝。对于建筑合理性阈值，要区分真实必需通行空间、设备/管井及推断细节，不能把所有小形状都作为相同硬错误。

利苑 6.1 Sol 首稿前共生成 72 个 patch 操作、17,149 参数字符，已超过首个声明的 16,061 字符。字符数只说明表达负担，不等于 token 或可节省时长。幸福中心 13 条重复连接的离线表达探针可用 984 字符 Python 数据与循环精确还原原 2,719 字符 JSON，输出哈希相同；尚未证明模型采用该接口会相应提速。

### 2.3 首稿后：停止原则已经写了，仍然花掉约半程

幸福中心 guide 已要求局部修改、复用未变区域检查、避免低收益细化、达到要求后直接 finish；不存在“完全没写停止原则”的简单缺口。但运行给的是 5,400 秒预算，尚未按 10 分钟目标组织完整交付。

C01 到 C03 未改变已有内部空间的几何布局；主要变化是增加一处屋顶空间、局部门与窗调整、用途证据和说明。最后一版 C03 在 22:11 已保存，之后仍用 4:25 完成核查和 finish，其中三次模型请求合计约 3:56。

全程所有工具执行仅约 1:56。即使把工具耗时降为零，原运行仍要约 24:40；“工具再快一点”不能单独实现 10 分钟。只削减首稿后的工作也不够，因为首稿本身已超过目标。

### 2.4 缓存：存在独立的接入/计量疑点，不能先认定修提示词就能解决

幸福中心首稿前：harness 报告输入 1,033,913、缓存输入 20,736（约 2.0%）；Codex 报告输入 1,231,526、缓存输入 1,143,424（约 92.8%）。重复输入的计数不代表独立信息量，也不能按比例直接推算速度或订阅账单。

对 22 个 harness 请求的实际发送体进行重建与哈希校验，确认模型设置和 tools 稳定，但历史中存在两类改写：旧尾部运行状态被移除再放到新尾部；超过保留批次数的历史图片改为文字引用。它们会破坏部分前缀的连续性。不过完整保留前一个输入的请求也有零缓存，说明不能用历史改写解释全部差异。

本轮通过同一订阅适配器做 6 次合成纯文本探针：无 key 和固定 key 各连续重复 3 次，各组实际发送体相同。每次输入 7,260 tokens、输出 OK（5 tokens），六次均报告 cached=0、cache_write=0；共 43,560 输入、30 输出，约 23.58 秒。固定 key 也未得到相同的服务端回显。原计划 8–12k 输入，实际分词为 7,260，保留这一规模偏差。

这说明该接入在本次重复文本条件下也没有报告命中。尚不能由此断言服务端禁用缓存、回执一定准确，或所有时间差由缓存造成。须对照 Codex 接入和支持参数，分别验证传输、缓存行为与计量。

补充同日同版 Codex CLI 的 3 次独立会话探针：同一合成提示，每次输入 18,051、缓存 9,216、输出 OK（5 tokens），没有工具调用；共约 28.51 秒。固定缓存量可能只覆盖 CLI 的固定说明，不能证明合成用户文本也命中。CLI 内建说明、工具定义、会话管理与直接 HTTP 路径不同，这不是发送体完全相同的因果对照。历史 Codex 对照也在 cache_write=0 时报告大量缓存读取，因此 cache_write=0 不能用来判定未写缓存或禁用缓存。

本轮合计新增 9 次模型请求，97,713 输入 tokens（其中报告缓存输入 27,648）、45 输出 tokens；没有新增建筑生成调用。下一步若继续定位，应使用达到预定规模的较长文本与同会话续写，分离固定前缀命中、用户文本命中与订阅计量差异，再分别测状态追加和图片保留策略。本轮不继续扩大探针，也不盲加 key、模拟 headers 或永久保留全部图片。

官方说明要求可复用前缀匹配并保留历史；缓存并不省去新输出的生成。公开 API 说明不能直接证明订阅接入支持相同参数或计费方式。参考：[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)。

### 2.5 更快不等于过关，source BIM 也还不等于可直接仿真

6 Sol 利苑正式输出了 C03，因此问题是质量失败，不能记成“没出结果”。已发现原图中的斜向核心筒与其输出轴对齐矩形井道不一致。首个草稿已经用 `rect` 表达电梯；最终 draft_007 的 lift1 仍为 `rect=[-5.2,2.2,-3.7,3.8]`，adopted 和最终 source 只是原样展开为四点。因此这一处不是编译器把正确旋转几何改歪，而是上游判断/表达选择出错。

声明引用的 view_0002 元数据是 23F 核心筒裁切，2 倍放大至 1210×530。尚未核验该图片真正进入 API 的载荷，仍不能排除图像投递或提示诱导，也不能由此判定模型永久做不好。必要时下一阶段做局部“识读关系→表达几何”的分离对照，不用整楼重跑替代归因。

当前后端只读转换探针中，幸福中心 harness、Codex 和两份利苑产物均未通过 `derive_ep_geometry`：分别首先遇到 holes、不区分证据不确定性的 warning 门槛、holes、非正交源多边形限制。旧文件 hash 全部不变，没有运行仿真。第一条错误不是完整问题清单，也不代表各产物的建筑质量相同。

因此现在不能拿“已可接街区仿真”解释多花的时间。应把下游适配作为独立工作包，保留统一出口，不能为兼容后端而把正确建筑轮廓改成矩形或把孔洞填掉。

## 3. 建议的实现方向

### A. 保留领域能力，缩短模型到产物的表达距离

推荐提供一套薄的建模 SDK/工具层：同一几何内核、统一 source BIM 出口和证据关系，允许模型用简短声明或受约束的代码表达局部坐标、重复楼层、共享边、孔洞和连接。将坐标变换、实例展开、边界与门宿主配对、接触关系和导出交给确定性工具。

重点不是再增加大量案例专用操作。现有 `primitive_frames`、局部坐标转换和 `local_baseline` 已实现且在说明中提供，应先使模型能更容易选用这些能力，而非再建一套。新增实验聚焦已暴露的共享节点/边身份、连续核心之间的批量关系及模板局部差异。复用现有修改影响范围和检查机制，正确几何不能靠模型重复手抄保持一致。

比较两种可实现路线：

| 路线 | 收益假设 | 风险及选择方法 |
|---|---|---|
| 精简声明接口 | 保留现有可靠内核，用共享引用与实例化缩短重复表达 | 避免继续无限扩充 DSL；用历史声明的等价编译长度及模型整案回合数验证 |
| 受约束代码 + 同一领域 SDK | 循环、函数、局部坐标等由通用语言表达，复用模型编程能力 | 需隔离写入与依赖；禁止绕过统一编译/核查；用同案例、同合同比较生成与修复成本 |

先做可切换的最小路径实验，再决定默认接口，不提前全面重写。一般编程执行提供表达能力，领域 SDK 提供跨案例可复用的几何与建筑语义；它们不应是二选一。

### B. 检查应产生少量明确决策，而不是更多自主查阅任务

保留两个质量层：确定性检查负责几何、宿主、拓扑与保存一致性；模型负责资料吻合、必要功能和建筑推断。一次保存返回足够判断的当前产物摘要、受影响视图和具体缺陷，不再让模型为拼齐状态反复读取多个清单。

默认首稿后做一次完整合理性判断，将已知必修问题合并修改；修改后复查受影响关系。只有明确会影响用户交付的剩余矛盾，才继续花预算。不能把“只许返工一次”当质量定义，也不能把失败强制标为完成。

先设完整交付的时间/成本预算，再让模型安排工作。两案可用“约 6–7 分钟已有完整候选、留 2–3 分钟核查和交付”作为实验预算分配；这只是待验证的目标，不是已经测出的速度，也不是固定阶段顺序。现有 `parametric_field_diagnostics` 已有字段预检；应复用它，并试验 SDK 在同一次程序执行中的局部构造检查与合并反馈，而非另建 validator 或增加模型往返。只有实际减少发现错误的成本，才保留该机制。

### C. 细度继续由模型结合资料和收益判断

此次不再先设计一套 60/80 分的细度规范。统一原则是保留已知有效信息、补足必要功能和通达性、停止低收益展开；可以保留用户的时间/成本偏好，但偏好不能降低最低合格门槛。

资料丰富部位直接利用已识读细节；资料缺失部位作最少但有用的建筑推断，并记录依据和范围。合并只在表达与用途确实需要时做，不能把“模型已经判断准确的多个房间”再故意粗化。

### D. 领域价值与自研 runtime 的价值分别证明

不要求证明“通用 Agent 从原理上永远做不到”。需要证明在同输入、同模型、同预算和同交付合同下，领域积累能够重复减少建模工作并提升产物。若自研 runtime 没有收益，应复用成熟 runtime，保留有效领域能力；自建循环本身不是毕设成果的必要条件。

核心对照建议为：

1. **A：通用 Codex + 原始资料 + 输出合同**，延续现有控制组。
2. **B：同一 Codex + 精简领域 SDK/工具**，只改变领域能力，用于证明 domain 的增量收益。
3. **C：自研 runtime + 与 B 相同的领域能力**，用于判断自研上下文、调度与预算是否增益，或反而拖累。

现有旧 harness 留作历史 D 组；没有必要每次全部四组重跑。先用窄探针筛掉无效机制，再进行最小端到端对照。不要同时换模型、接口、提示词和验收口径后把变化归于某一个因素。

## 4. 经共同审阅后再实施的顺序

| 阶段 | 工作内容 | 必须交出的证据 / 退出条件 |
|---|---|---|
| P0：冻结比较协议 | 同资料/合同/模型设置；统一时间起止、质量评阅、token 与成本口径；新目录和上下文隔离旧答案 | 旧结果只作诊断基线；质量事实卡在看新结果前冻结；生成端不得读取旧产物、GT、参考几何或评分，工具示例不得含本案答案 |
| P1：消除确定性损耗 | 修共节点规整、公差与宿主传播；批量返回真实缺陷；拆分数学错误与建筑政策 | 离线复现错误消失，真实穿墙/重叠仍被拒绝；无资料无依据的几何不被自动美化 |
| P1 并行：接入与上下文 | 确认缓存/计量差异；稳定可复用历史，限制巨量状态回流，按需取图/细节 | 实际 wire、缓存回执、等待/生成时间分开；回执异常未解释时不承诺缓存提速比例 |
| P2：缩短表达与收尾 | 两种薄接口小实验；一次编译返回终检材料；合并必修项，增量复查 | 相同语义输出、更少声明与模型回合；不是删除质量检查或把不确定性藏起来 |
| P3：单 Agent 验收 | 幸福中心、利苑先用同一强模型做 A/B/C 对照；候选路径通过后重复运行 | 两案完整交付均 ≤10 分钟且相对同模型通用对照至少快一半；质量和成本分别达标 |
| P4：泛化与较便宜模型 | 一个保留不用来调参的新案例；仅 mesh 与另一种输入组合；再测 6 Sol 或其他经济模型 | 不是案例硬编码；明确哪些模型/任务可用、失败率及可恢复边界；失败成本计入 |
| P5：真实仿真连接 | source BIM 到仿真派生模型的适配与空间映射；再完成街区试点 | 同一冻结源 BIM、可追踪派生关系、几何守恒与接触一致、实际引擎运行和结果核查 |
| P6：生产分工 | 仅对可独立且有收益的识读/核查并行，使用已优化单 Agent 基线 | 两案完整交付 ≤5 分钟，同时报告总 token/成本、合并返工与质量；没有收益就不默认启用 |

P5 的能力缺口现在就应设计边界，但不能借机扩张 P1–P3 的范围。当前的 10 分钟先验收完整 source BIM 交付；街区仿真另计导出、配置、求解与人工补录成本，并明确哪一步尚未自动化。

## 5. 验收协议建议

### 速度与稳定性

- 端到端时间从提交冻结输入，到正式交付完成、必要产物落盘且可查看、必要自检完成、全部工作模型和子任务终态；包含预处理、模型等待、重试、导出与恢复。仍有后台检查或修改时不能停钟。独立事后评阅不计生成时长，但评阅失败则该次不算合格交付。
- 冷启动和可复用缓存分别报告；不把为某案例手工预制的观察或模板移出计时。
- 首轮每案每组 1 次用于筛选；冻结候选后，每案候选与通用 A 组均至少做 3 次匹配重复，交错执行，全部报告，不挑最好的一次。历史或筛选单次只作参考；3 次只能证明小样本可重复性，不声称高可靠率。当前利苑尚无同模型通用 Codex 的正式整案对照，需在 P3 补齐。
- 验收要求重复测试中每次都在 10 分钟内且合格，并报告中位数与最慢值；相对通用对照的 50% 收益用相同计时口径比较。运行顺序交错，固定版本并记录服务异常。

### 质量

- 统一独立渲染器和评阅材料，隐藏组别；评阅者能看到原始资料、必要来源说明与推断范围，不能看到生产轨迹来形成先入为主。
- 比较主要形体/楼层/立面、已知平面空间组织、水平和竖向通达、缺失信息下的推断、源模型的可派生性。以用户已说明的最低可用标准和少量正反例锚定，具体建筑判断仍由模型与人工评阅承担。
- 确定性检查通过是必要条件之一，不是质量分；窗/房间数量、候选数量、返工次数均不作为质量奖励。
- “更好”必须指出预先关注的质量维度上有可复核改善，且其他关键维度无实质退步；若只是质量相当但更快更省，如实写相当，不能宣称三项目标全部完成。
- 利苑斜向核心筒识读/坐标问题应加入失败样例；无依据的额外隔墙、必要房间无法到达、跨层井道被楼板切断等也作为审阅锚点。它们不是穷尽所有情况的硬编码规则集。

### 成本

- 每次记录总输入、缓存输入、未缓存输入、输出、模型回合、失败与恢复消耗；所有 workers 一并计入。
- 同模型的 token 节约和不同模型的价格节约分开；有实际账单时报告账单，无账单时列明按公开/配置价格估算。订阅额度不能伪装成精确美元成本。
- 建议把同模型总 reported tokens 至少减少 30% 作为首轮工程筛选线，同时要求未缓存输入与输出没有把成本推高；这一数值为待共同确认的实验门槛，不冒充用户已定标准。
- 比较每次尝试与每次合格交付的成本，后者包括失败尝试，不能用廉价模型失败更多来制造“更省”。

### 仿真与通用性

不将源空间直接等同热区；明确合并/分区策略、门与开放通道、虚边界、连续井道、孔洞及非正交表面的转换语义。派生时可做后端必需拆面，但保留源实体映射和面积/体积/窗面积等守恒核验。不能靠改 source 的标签、删除 warning 或隐藏失败来通过。

街区试点不只要求求解器退出成功，还应记录建筑数、输入缺失、自动完成率、人工补录量、整体计算成本和关键结果的合理性核查。当前四份转换探针不支持任何“已实现街区仿真闭环”的结论。

建议最小范围先采用固定天气、物性、用途时刻表及理想负荷系统假设；共同坐标、尺度、真北和建筑位置一致。完成真实引擎运行，并至少对同一建筑比较独立场景与加入邻楼遮挡的场景，核对遮挡及太阳得热响应。该范围待共同审阅，不自动扩大到实际 HVAC、CFD 或实测校准。

## 6. 本轮建议共同确定的决策

1. 先修确定性返工与接入疑点，再做薄接口实验；不继续堆提示词和案例专用工具。
2. 用 Codex + 领域 SDK 的 B 组直接检验领域价值，允许据证据复用通用 runtime。
3. 默认按输入和价值自动选择细度，把用户偏好体现为时间/成本投入；最低质量不随预算标签下降。
4. 先过单 Agent 两案 10 分钟门槛，再推广输入类型、测试经济模型和做 5 分钟分工。
5. source BIM 与仿真派生明确分层，后端桥接单独验收，不改变当前公平对照的出口。

这些是建议实施顺序，不是本轮已经改入代码的内容。若完成 P1/P2 后同模型对照仍无明显收益，应缩减或替换无效模块，而不是用更多检查和工程复杂度解释结果。
